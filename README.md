# auto-giga-recruiter

CLI-утилита, которая входит в твой Telegram-аккаунт, открывает бота **ГигаРекрутер**, выбирает вакансию и проходит ИИ-интервью за тебя. Ответы генерирует **Codex** на основе твоих резюме из папки `resumes/`.

```
╭───────────────────────────────────────────╮
│            auto-giga-recruiter            │
│ ИИ-интервью в ГигаРекрутере на автопилоте │
╰───────────────────────────────────────────╯
╭ 🤖 ГигаРекрутер ─────────────────────────────╮
│ Расскажите о самом сложном проекте.          │
╰──────────────────────────────────────────────╯
                 ╭──────────────── 🧑 Я · 412/800 симв. ╮
                 │ В прошлом году я переводил платёжный │
                 │ монолит на микросервисы…             │
                 ╰──────────────────────────────────────╯
```

## Как это работает

- **Telegram:** по умолчанию утилита управляет **Telegram Web** в невидимом браузере ([Playwright](https://playwright.dev)): открывает чат с ботом, читает сообщения, нажимает кнопки и печатает ответы. Вход по QR-коду прямо в терминале, `api_id`/`api_hash` не нужны. Есть альтернативный драйвер `mtproto` на [GramJS](https://github.com/gram-js/gramjs), если ключи с my.telegram.org у тебя есть.
- **ИИ:** установленный [Codex CLI](https://developers.openai.com/codex/cli/) через `codex exec`, с сохранённым входом через ChatGPT. Ключ API не нужен; отдельного API-провайдера нет. На каждом шаге Codex получает историю интервью, новые сообщения бота и список кнопок, а возвращает структурированное действие: `reply` (ответить текстом), `click` (нажать кнопку), `wait` (ждать дальше) или `finish` (интервью окончено).
- **Выбор резюме:** резюме подбирается под вакансию само, по названию и описанию. Ключевые слова берутся из имени файла: `resume.vue.md` выбирается, если в вакансии упоминаются Vue, Nuxt, Pinia; `resume.react.md`, если React, Next.js, Redux. Если стек не понятен, берётся `resumes.default`, а без него резюме с `react` в имени.
- **Живой текст:** ответы пишутся как набранные человеком на клавиатуре. Длинные тире, ёлочки, символ многоточия, стрелки заменяются на обычные символы; если в ответе оказался иероглиф или эмодзи, ответ уходит модели на переделку.
- **Контекст:** резюме и правила ответа передаются как инструкции модели, история хранится в памяти приложения и отправляется на каждом шаге. В конце показывается статистика токенов Codex, включая кешированные; стоимость в долларах не рассчитывается.
- **Лимит символов:** модели передаётся лимит; если ответ длиннее, она дважды получает просьбу сократить его; если и это не помогло, текст обрезается по границе предложения.
- **Имитация человека:** перед отправкой показывается статус «печатает…», задержка пропорциональна длине ответа. Прежде чем отвечать, утилита ждёт, пока бот допишет серию сообщений.

## Установка

Нужен Node.js 20+ и установленный Codex CLI. Интеграция проверена с `codex-cli 0.166.0`; при ошибке неизвестного флага обнови CLI.

```bash
npm install -g @openai/codex
codex login               # вход через ChatGPT
npm install
npm run setup              # скачает Chromium для Playwright (~150 МБ, один раз)
npm start -- init          # создаст config.yaml и .env из примеров
```

1. Проверь вход: `codex login status`. Нужна авторизация через ChatGPT, предоставляющая доступ к Codex. Приложение исключает `OPENAI_API_KEY` и `CODEX_API_KEY` из окружения генератора; пользовательский `~/.codex/config.toml` не загружается, а штатное хранилище авторизации Codex сохраняется.
2. Положи резюме в `resumes/` (`.md` или `.txt`). Образец: `resumes/example.md`.
3. Проверь `bot.username` и `answers.maxChars` в `config.yaml`.

```bash
npm run login              # в терминале появится QR-код: Telegram на телефоне → Настройки → Устройства → Подключить устройство
                           # если включена двухэтапная проверка — спросит облачный пароль
npm start -- status        # проверка: конфиг, резюме, бот найден
```

Если браузер не запускается в WSL/Linux из-за системных библиотек, выполни `sudo npx playwright install-deps chromium`.

## Использование

```bash
# 1. Разведка: посмотреть, как устроен бот (сообщения, кнопки, callback data)
npm run recon                        # отправит /change_vacancy и будет слушать (--no-send — только слушать)
npm run recon -- --interactive       # сам нажимаешь кнопки и отвечаешь из CLI
#    Дамп сохраняется в data/recon/*.json, HTML чата — в data/recon/*.html
#    (если Telegram поменял вёрстку, по нему правятся telegram.web.selectors в config.yaml)

# 2. Репетиция без Telegram: вопросы интервьюера вводишь ты, отвечает ИИ
npm run dev -- --dry-run
#    Кнопки задаются так: «Готовы начать? || Да | Нет»

# 3. Боевой режим. При запуске и после каждого интервью отправляется /change_vacancy
#    (/start в этом боте не работает); если бот промолчал, запрос повторяется.
npm run dev                                # вакансию выбираешь из списка кнопок; после интервью снова меню
npm run dev -- --all                 # пройти все доступные интервью подряд (то же: пункт меню «🚀»)
npm run dev -- --vacancy "Java"      # вакансия выбирается сама (подстрока или индекс кнопки)
npm run dev -- --confirm             # каждый ответ одобряешь, правишь или перегенерируешь
npm run dev -- --resume backend.md   # явно указать резюме (по умолчанию выбирается по стеку вакансии)

npm run help                               # все команды и их опции (npm run help -- interview — одна команда)
npm run resumes                            # список резюме и приблизительный размер в токенах (локальная оценка)
npm run logout                             # удалить сессию с диска
```

У `login`, `recon` и `interview` есть флаг `--headful`: он показывает окно браузера, чтобы видеть, что происходит. В WSL для этого нужен WSLg (есть в Windows 11).

`Ctrl+C` один раз останавливает интервью и сохраняет транскрипт, второй раз завершает процесс сразу.

## Конфиг

Все параметры с комментариями — в [`config.example.yaml`](config.example.yaml). Основные:

| Параметр | Что делает |
|---|---|
| `telegram.driver` | `web` (по умолчанию, браузер) или `mtproto` (нужны `TG_API_ID`/`TG_API_HASH`) |
| `answers.maxChars` | жёсткий лимит символов в одном ответе |
| `answers.honesty` | `strict`: только факты из резюме, без выдуманного опыта |
| `answers.extraInstructions` | чего нет в резюме: зарплата, формат работы, срок выхода |
| `behavior.mode` | `auto` (по умолчанию) или `confirm` |
| `behavior.typingDelay` | диапазон задержки «печатает…» |
| `behavior.questionTimeoutSec` | если у бота есть таймер на ответ, задержки подстроятся под него |
| `resumes.perVacancy` | правило «регулярка по названию вакансии → файл резюме» |
| `llm.provider` | `codex`: все запросы через Codex CLI |
| `llm.model` / `llm.effort` | необязательная модель Codex (без неё стандартная модель CLI) и глубина рассуждений |

### Переход со старого конфига

Значения `llm.provider: auto`, `claude-code` и `api` принимаются для совместимости и направляются в Codex с предупреждением. Модель `claude-*` заменяется стандартной моделью Codex CLI. Старые `llm.maxTokens` и `llm.fallbacks` игнорируются с предупреждением: удали их и укажи `provider: codex`. Приложение не переписывает твой `config.yaml`.

`ANTHROPIC_API_KEY` больше не используется, даже если остался в локальном `.env` или старом шаблоне. Для браузерного драйвера Telegram ключи не нужны; для mtproto сохраняются `TG_API_ID`, `TG_API_HASH` и `SESSION_PASSPHRASE`. Команда `resumes` оценивает токены локально по числу UTF-8-байтов; это приблизительное значение, не точный токенизатор модели.

### Диагностика Codex

- CLI не найден: установи `npm install -g @openai/codex` и проверь `codex --version`.
- Нет авторизации: выполни `codex login` и выбери вход через ChatGPT.
- Исчерпан лимит: дождись его сброса; автоматического переключения на платный API нет.
- Модель или глубина рассуждений недоступны: убери `llm.model` либо выбери доступную модель и поддерживаемый `llm.effort`.
- Сетевая ошибка, таймаут или невалидный ответ: приложение повторит запрос до трёх раз. Таймаут одного вызова — пять минут.

## Безопасность

Личные данные держатся **вне git**; публичность репозитория не предполагается:

| Что | Где | В git? |
|---|---|---|
| Для mtproto: `TG_API_ID`, `TG_API_HASH`, `SESSION_PASSPHRASE` | `.env` | ❌ |
| Авторизация Codex | штатное хранилище Codex вне проекта | ❌ |
| Сессия Telegram Web (даёт **полный доступ к аккаунту**) | профиль браузера `data/browser-profile/`, права 700 | ❌ |
| Сессия mtproto | `data/session.enc`, права 600, AES-256-GCM при заданном пароле | ❌ |
| Резюме | `resumes/*` (кроме `example.md`) | ❌ |
| Транскрипты интервью, дампы recon | `data/` | ❌ |
| Личный конфиг | `config.yaml` | ❌ |
| Телефон, пароль 2FA | нигде, вводятся интерактивно | — |

Для генерации создаётся отдельная папка в `logging.dir/codex-workdir/`: схема и инструкции с правами `600`, папка с правами `700`. После вызова она удаляется. История отправляется через stdin, резюме не попадает в аргументы процесса. Вызовы используют `--ephemeral`, песочницу `read-only`, отключённые shell, веб-поиск, приложения, плагины и хуки. Резюме и сообщения интервью передаются OpenAI для генерации ответов. Обычные транскрипты приложения управляются `logging.saveTranscripts`.

Дополнительно:

- **Pre-commit хук** (`scripts/guard-staged.mjs`) не даёт закоммитить `.env`, `config.yaml`, `data/`, файлы сессий и личные резюме, а также прогоняет [secretlint](https://github.com/secretlint/secretlint) по индексу. Хук ставится автоматически при `npm install`; вручную: `npx simple-git-hooks`.
- Логи и транскрипты проходят через redaction: ключи, api hash, телефон и строка сессии заменяются на `***`.
- Проверить весь репозиторий: `npm run secretlint`. Для надёжности можно дополнительно прогнать [gitleaks](https://github.com/gitleaks/gitleaks): `gitleaks detect`.
- Профиль браузера не шифруется: не копируй папку `data/` и не отдавай её никому.
- Если `logging.dir` указывает внутрь репозитория, папка обязана быть в `.gitignore`, иначе утилита не запустится: там лежат сессия и транскрипты.
- Если сессия могла утечь, выполни `npm run logout` и заверши сеанс «Telegram Web» в приложении: *Настройки → Устройства*.

## Риски и ответственность

- Telegram может ограничить аккаунт за автоматизацию. Браузерный режим выглядит как обычный Telegram Web, но задержки всё равно включены по умолчанию; не убирай их.
- Если Telegram обновит вёрстку веб-версии, браузерный режим может перестать видеть сообщения или кнопки. Тогда запусти `npm run recon` и поправь селекторы в `config.yaml` по сохранённому HTML. В дампе есть реальные сообщения чата: прежде чем кому-то его отправлять, убери из него личное.
- Правила ГигаРекрутера и работодателя могут запрещать прохождение интервью ассистентом. Решение и ответственность за использование — на тебе.
- ИИ может ошибаться. При `honesty: strict` модель не придумывает опыт, но перед важными интервью прогони `--dry-run` и `--confirm`.

## Разработка

```bash
npm run typecheck
npm test
node scripts/tests/guard-staged.mjs
npm run build              # сборка в dist/ (tsup)
```

Структура: `src/telegram/web/` — браузерный драйвер (вход по QR, чтение чата, селекторы); `src/telegram/` — общий интерфейс чата и драйвер mtproto; `src/llm/` — Codex CLI, промпты и схема действий; `src/interview/` — навигация, цикл интервью и recon; `src/ui/` — отрисовка в терминале.

Инструкции для работы в Codex находятся в [`AGENTS.md`](AGENTS.md). Запускай Codex из корня проекта. Конфигурации `CLAUDE.md` и `.claude/` для разработки и работы приложения не требуются. Создавай локальные коммиты после завершения логических изменений, не отключай pre-commit и выполняй push только по явному запросу.
